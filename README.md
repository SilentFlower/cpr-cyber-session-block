# Cyber 会话封禁

OpenAI 实际返回 `cyber_policy` 后，限时禁止同一对话继续请求，并在 CPR 扩展页保留记录

插件独立于 `cpr-session-failover`，可以同时安装。默认封禁 **一小时**，在「会话封禁记录」的「插件设置」中调整，支持提前解除

## 宿主要求

使用官方原版 CPR >=3.43.0，插件仅依赖公开 SDK、插件私有状态与既有管理 API，不需要修改或重启 CPR

正常响应通过宿主原始正文句柄直接交付，插件不读取、复制或转发响应帧。封禁依据来自 `next` 返回的结构化上游错误，或请求完成观察触发查询后核实的原生错误记录

失败记录尚未落库时，持久化待核实的请求归属；下一轮准入、管理页查询和每 30 秒维护都会继续核实

## 安装与使用

1. 从 [GitHub Releases](https://github.com/SilentFlower/cpr-cyber-session-block/releases/latest) 下载 Linux x86_64 安装包与 `.sha256` 文件，或按[开发说明](docs/development.md)自行构建
2. 在 CPR「插件管理」通过 GitHub 来源填写 `SilentFlower/cpr-cyber-session-block`，选择对应的 `.tar.gz` 附件；也可直接上传安装包，校验来源与摘要后安装
3. 检查 request、attempt、retry 与 observer 绑定启用且覆盖相同范围；observer 只需 `request_completed`，移除宿主默认生成的 `websocket_response` 绑定
4. 从左侧插件导航打开「会话封禁记录」，查看触发请求、到期时间及本地拦截次数

同时使用其他重试插件时，将本插件的重试绑定排在主动要求重试的策略之前

首次失败保留原始上游错误。同步错误确认命中后停止本次请求的后续自动换号重试；未确认命中时沿用宿主重试策略

请求完成观察为异步尽力投递，流式失败的封禁在通知处理并核实后生效，紧接着到达的请求可能已经进入上游。观察过载、关联缓存淘汰或插件重启可能丢失尚未处理的通知；已持久化的待核实记录仍会继续处理，观察失败不会改写模型响应

封禁期间的新 HTTP/SSE 请求在选号前返回 `403` / `session_blocked_by_cyber_policy`；原生 Responses WebSocket 使用宿主标准 `403` / `policy_denied` 错误。已经通过准入但仍在等待的请求，会在上游尝试开始前再次检查

原生记录尚未落库时，同会话后续 HTTP 请求暂时返回 `503` / `session_policy_pending`，WebSocket 返回宿主标准临时错误，不向上游发送。核实为普通错误即恢复；核实为策略命中则从原失败时间计算封禁，延迟不会延长封禁期限。超过原时长仍无法核实的事件停止阻断，不标记为策略命中

已经发往上游的并发请求继续执行。修改时长只影响后续新命中，封禁期间的本地重试不延长到期时间。到期自动允许后续请求，无需后台任务

## 会话身份

使用认证后的 Key ID 和明确会话身份生成 SHA-256 摘要，不封禁账号或整个 Key。不同 Key 的同名会话相互独立

优先沿用现有会话插件的 turn metadata、`client_metadata.session_id`、正文 `session_id`、`session-id` 和 `context.session_id`；同时支持 `session_id`、`conversation_id`、`X-Session-Id`、`X-OpenCode-Session`、`X-Conversation-ID` 请求头

共享 Key 的转发网关应为不同用户的对话提供独立且稳定的会话 ID。`prompt_cache_key`、IP、User-Agent、请求内容及历史相似度不用于封禁身份。没有明确会话身份时原样交给宿主，不建立跨请求封禁

仅结构化错误码 `cyber_policy` 触发规则，普通 `unavailable`、响应未完成、断网或请求正文中出现这个词都不会触发

## 记录与恢复

记录保存于宿主插件私有状态，重启和参数更新后保留。停用插件停止拦截，重新启用时尚未到期的封禁继续生效

记录列表展示触发账号 ID，触发、到期和解除时间统一显示北京时间（UTC+8）

页面支持请求 ID、会话摘要或 Key ID 搜索、状态筛选、分页、详情和手动解除。解除只针对所选记录，不会解除同会话后来建立的新封禁，也不清除宿主或上游自己的限制。保存参数后，点击宿主标题右侧「刷新页面」重新连接；解除结果未知时先刷新记录核对，不自动重试写入

持久记录不自动删除，受宿主配额限制：命名空间总计 16 MiB，64 个分片中每个最多 256 KiB。封禁、历史和待核实归属在同一个对象里原子更新，配额耗尽不会淘汰已有有效封禁。写入失败会保留原上游错误并报告宿主日志，但不能宣称新封禁已持久化；读取或本地拦截记账失败时 HTTP 返回 `503` / `session_policy_unavailable`，WebSocket 返回宿主标准临时错误

记录不保存请求正文、完整会话 ID、认证头、Key 明文或原始上游错误转储
